# Site audit, November 2026

A full pass over the site after the full-width layout redesign (#67) and the
four new languages (#69). Run on 2026-11-14 against production
(`mlbbdex.com`, HTTP checks, read-only) and a local production build of
`develop` (browser checks), then again on the fixed build.

## What was checked

| Check | Scope | How |
| --- | --- | --- |
| HTTP crawl | 25,929 URLs: the 25,767 `<loc>` of the 14 child sitemaps (all 9 languages), plus 162 static, paginated, private and 404 routes absent from them | Node, 4 concurrent requests, `MLBBDex-audit` user agent, `/api` skipped |
| Per page | status, redirects, response time; `<title>`, meta description (present, length, duplicates within a language), one `<h1>`, `lang`, canonical, hreflang (9 languages + `x-default`, reciprocal), JSON-LD that parses, leftover message keys, `undefined` / `NaN` / `null` / `{placeholder}` in visible text and attributes, French prose on other languages, links and images without accessible names | HTML parsed with `node-html-parser` |

## Findings and fixes

### Hero analyses shown in French in every language — fixed

The 38 written analyses (`src/data/heroes/`) were rendered as is on all nine
languages: the crawl found French prose on every analysed hero page of
`en`, `es`, `fil` and the other languages, including the written builds' emblem
("Emblème de tank").

- New `analyses` dataset in `scripts/translate-data.mjs`, like the tier list
  notes: the French source is read from the TypeScript role files, only the
  prose is translated (summary, paragraphs, skill descriptions, strengths,
  weaknesses, build names and contexts), into `src/data/game/analyses/<lang>.json`.
  It runs with `npm run translate`, so the nightly sync keeps it current.
- Item, talent and spell names are sent behind markers (the style rule keeps
  them in English: "sans Flicker" had become "without flickering"), and a
  few French MOBA nouns are reworded before sending ("tank d'engagement" came
  back as a *betrothal* tank in Russian, Thai and Indonesian; "file classée" as
  a "classified line").
- `analysisFor(analysis, locale)` in `src/lib/data.ts` overlays the
  translation on the source: slugs, items, cooldowns and order stay with the
  French file; an analysis not translated yet, or a list whose length changed
  since, stays in French rather than misalign.
- The hero page, its meta description (when no measurement exists) and the
  written builds use it; the emblem of a written build is shown as its role in
  the page's language, like the played builds; a one-line note says the
  analysis was machine-translated from French.
- Tests: `tests/unit/analyses.test.ts`, an e2e check on `/en/heroes/tigreal`,
  and the smoke check now fails if the Khufra page shows its French analysis
  in another language.

### Metadata — fixed

- **Stale hero count on every page**: the default description said "all 133
  heroes" in the nine catalogues while the game has 134 (it was a literal in
  the message). It now takes `{heroes}` from the data.
- **Duplicate title**: the Advance Server hub had the same `<title>` as its
  latest version page in every language. The hub now has its own title.
- **Short descriptions**: the seven forum category pages had 47–52 character
  descriptions (the category subtitle alone); they now name the forum too.
- **Lost language on sign-in**: `/<lang>/account` without a session redirected
  to the unprefixed `/login`, which the proxy then sent to the browser's
  language (`/it/account` → `/en/login` for an English browser). It now
  redirects to `/<lang>/login`.
- **Contribution guide**: pointed at `src/data/heros/`, renamed long ago to
  `src/data/heroes/` (all nine languages).
- Indonesian win–loss records read "V – D" (French initials); now "M – K".

### Layout and accessibility — fixed

- **Horizontal overflow at 360 px on `/watch`**: the news grid had no column
  template, so a long unbroken word in a post title widened the page to
  381 px. One `minmax(0, 1fr)` column and `break-words`.
- **Layout shift**: `/tools/collection` (CLS 0.15–0.38 depending on width),
  `/quiz` (up to 0.17 at 768 px) and `/mlbbdle` (0.02–0.05): the loading
  placeholder was a short line, so the rules and method sections jumped down
  when the game or the catalogue arrived. The placeholders now reserve about
  the height of what replaces them. CLS is 0 on the fixed build.
- **Mobile sheet and the keyboard**: with the menu open, Tab from the burger
  went to the page links hidden behind the sheet, and Escape sent focus to a
  section button that had just disappeared. Tab and Shift+Tab now cycle
  through the header and its sheet (search, language and account included),
  and Escape returns focus to the burger (e2e test added).
- **Unnamed links in patch notes**: 333 empty `<a>` on 72 patch note pages,
  left over from the wiki's item icons (the sanitiser strips the image, the
  link stayed), announced with no name by screen readers. `cleanHtml` now drops links left
  without text (unit test added).
- Header controls on phones were 30, 32, 36 and 40 px high side by side
  (search, language, login, menu); search and language are now 36 px like
  login.

### Checked and clean

- **Status codes**: 25,911 pages answer 200 and the 18 deliberate 404 probes
  answer 404. The 22 redirects are all expected: the bare `/`, `/heroes` and
  `/tier-list` to a language (307), `/fr/heroes/` to drop its slash (308),
  `/<lang>/account` and `/<lang>/account/profile` to the login page without
  a session (see the language fix above).
- **Response time** (production, 4 at a time): p50 434 ms, p90 604 ms, p99
  878 ms, slowest 2.3 s. Patch notes (p50 843 ms) and Advance Server versions
  (757 ms) are the slowest routes; nothing timed out.
- **Head**: every page has one `<title>` (the second one counted on `/compare`
  is an SVG `<title>`), a meta description, a `lang` matching its language,
  a canonical to itself and the nine hreflang alternates plus `x-default`,
  all reciprocal and all answering 200. No duplicate title or description
  within a language apart from the Advance Server hub (fixed).
- **One `<h1>`** on every page.
- **JSON-LD**: 51,424 blocks, all parse.
- **Visible text and attributes**: no `undefined`, `NaN`, `null` or
  `[object Object]`, no leftover message key, no raw placeholder (the API
  documentation shows `{slug}` and `{version}` on purpose; the few "key" hits
  were a sentence ending in "roles." glued to a "Learn more" button by the
  text extraction). No message key is missing from any catalogue.
- **Links**: the 56,902 distinct internal hrefs all resolve: the 25,929
  crawled pages, 1,998 more paths fetched once, and 60 sampled out of the
  30,294 `/compare?a=…&b=…` and calendar filter links, all 200.
- **Images**: no `<img>` without `alt` on any page; the 300 sampled sources
  all answer 200; no broken image in the browser runs.
- **Browser**: no hydration warning; no console error besides the 404 page's
  own status and `429` from `/api` while five audit browsers shared one
  address; no horizontal overflow besides `/watch`; no clipped text besides
  skin names clamped to two lines on purpose. Mega menus open on hover and
  on Enter, Tab enters the panel, Escape closes it and returns focus. The
  sticky header (66 px) does not cover anchored headings in patch notes and
  guides. The win-rate tool works from the keyboard alone, with visible focus.
- **Performance** (fixed build, slow 4G and 4× CPU): LCP 1.0–1.3 s, CLS 0,
  190–205 KB of compressed JavaScript on each measured page. The largest
  shared chunk is 73 KB gzipped. Nothing near the 2.5 s LCP or 0.1 CLS marks.

## Left as is

- **Translation quality of the analyses**: machine translation, like the
  patch notes and the hero stories. It reads correctly but not like a player
  wrote it ("Roam initiator", "low ranked game"). Hand corrections can go in
  the cache (`scripts/translations-data.json`), which the script never
  overwrites; the French stays the reference. `/api/v1/heroes/{slug}` keeps
  returning the French analysis.
- **The 404 page is empty in the server HTML**: Next sends its error shell
  (`<html id="__next_error__">`) and the localised 404 page appears once the
  client starts. The status is a correct 404 and browsers show the right
  page, but crawlers without JavaScript see an empty body, the home page's
  canonical and both `noindex` and `index, follow`. It comes from how Next 16
  renders `notFound()` here (with `experimental.globalNotFound`); it needs its
  own investigation, not a blind change.
- **Long titles and descriptions**: 10,684 titles exceed 70 characters
  (mostly Spanish, Filipino and Indonesian matchup pages: "Aamon vs Atlas:
  ¿quién gana? Estadísticas del duelo por rango (parche 2.2.16)") and 14 tool
  descriptions exceed 300 characters. Search engines cut them on display;
  shortening them is an editorial choice, not a bug.
- **Thai pages** shift by up to 0.09 at 1280 px while the Thai font loads,
  under the 0.1 mark.
- **`/bot` pages** answer 404 in a local build without
  `NEXT_PUBLIC_DISCORD_CLIENT_ID`, by design; they answer 200 in production.
- **Stale message corrections**: `npm run translate:messages` reports a few
  hand corrections whose French source changed since (`accountValueUI.importLead`,
  `collection.methodStorage`, `collectionUI.empty`, the bot greeting defaults
  in Indonesian…). Those messages show the machine translation until the
  correction is redone.

## How to run it again

The scripts are throwaway (not in the repository); the checks they make are
listed above. The parts worth keeping are in the regular suites: the
analysis translation test, the sanitiser test, the mobile sheet and analysis
e2e tests, and `scripts/smoke-check.mjs` for placeholders and missing
translations.
